# IndexTTS-2 本地部署设计

## 目标

在 Apple M4、16GB 内存的 Mac 上独立部署 IndexTTS-2，先完成本地 Web 试听和中文语音生成。确认音质、速度和稳定性后，再把它接入现有“芷春”FastAPI 服务。

## 本阶段范围

- 使用 IndexTTS-2 官方仓库和官方模型。
- 创建独立的 Python 3.11 环境，避免影响现有 FastAPI 环境。
- 使用 Apple MPS 运行推理。
- 启动官方本地 WebUI，并生成一段中文 WAV 作为验收样音。
- 使用用户拥有使用权的参考音频复刻目标音色。
- 记录启动方式、模型目录和常见故障处理。

本阶段不修改现有 `/chat` 接口，不加入语音识别，也不提供公网访问。

## 目录与隔离

IndexTTS-2 放在项目下的 `local_tts/indextts2/`，模型放在其 `checkpoints/` 中。代码、虚拟环境、模型权重和生成音频均不提交到 Git。

现有 FastAPI 服务继续使用当前环境。IndexTTS-2 使用 Python 3.11 和自己的依赖环境，避免与项目当前 Python 3.14 及依赖版本冲突。

## 运行方式

1. 安装或确认 Python 3.11、Git LFS、FFmpeg 和 `uv`。
2. 下载官方 IndexTTS-2 仓库。
3. 使用 `uv` 创建隔离环境并安装 WebUI 依赖。
4. 从 ModelScope 下载官方模型到 `checkpoints/`。
5. 不启用 CUDA、DeepSpeed、CUDA kernel 或 FP16。
6. 让官方代码自动选择 `mps`；如果 MPS 出现不支持的算子，再回退 CPU 进行故障定位。
7. 启动 WebUI，仅监听 `127.0.0.1:7860`。

## 音色与数据流

用户在 WebUI 中上传一段干净的参考音频，输入中文文本并生成 WAV：

`参考音频 + 文本 + 情绪设置 -> IndexTTS-2 -> WAV 文件`

目标音色为温柔、清冷、年轻女生。参考音频建议为单人、无背景音乐、无混响、语速自然的录音，并确保用户有权使用该声音。

## 资源控制

这台 Mac 只有 16GB 统一内存，因此：

- 首次只允许单任务生成，不做并发。
- 测试时关闭不必要的大型应用，减少内存交换。
- 先使用短句测试，再逐步增加文本长度。
- 模型保持独立进程；未来接入 FastAPI 时，不把模型直接加载进现有 Web 服务进程。
- 若 MPS 持续内存不足或速度不可接受，则停止接入，改用更轻的 Kokoro 或云端 TTS。

## 错误处理

- 缺少模型文件时，明确指出缺失文件，不静默下载后继续。
- 参考音频格式错误时，返回可理解的提示。
- 模型加载失败时保留完整本地日志，但不暴露到未来的公开 API。
- 生成超时或内存不足时终止当前任务，避免拖垮现有 FastAPI 服务。

## 验收标准

- WebUI 可以在 `127.0.0.1:7860` 打开。
- IndexTTS-2 明确使用 MPS 或给出可解释的 CPU 回退原因。
- 能用参考音频生成一段可正常播放的中文 WAV。
- 连续生成三次短句，进程不崩溃且内存可以恢复。
- 现有 FastAPI 测试仍然通过。

## 后续接入

本地试听验收通过后，第二阶段再增加独立 TTS API。现有 FastAPI 通过内部 HTTP 调用它，获得 WAV 或流式音频；TTS 服务设置单并发队列、超时和健康检查。这样即使 TTS 模型崩溃，也不会带崩聊天接口。

## 许可边界

当前阶段仅用于个人本地测试。IndexTTS-2 使用 bilibili 自定义模型许可；在公开部署、收费或商业化之前，需要重新核对届时生效的许可，并在需要时取得书面授权。
