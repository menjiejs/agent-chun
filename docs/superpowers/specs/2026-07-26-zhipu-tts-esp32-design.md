# 智谱 TTS 与 ESP32 播放接入设计

## 目标

把已经试听验收的智谱 `GLM-TTS` 正式接入“芷春”服务，并提供一个适合 ESP32 的独立 WAV 接口。ESP32 通过局域网请求语音，在不保存智谱 API Key 的情况下，经 MAX98357 I²S 功放播放“芷春”的回复。

## 使用边界

- 系统仅供用户个人在家庭或个人局域网内使用。
- Mac 与 ESP32 连接同一个 Wi-Fi，由 Mac 运行 FastAPI 和调用智谱。
- TTS 固定使用 `glm-tts`、`tongtong` 音色和 WAV 输出。
- 本阶段只完成文本转语音和扬声器播放，不加入麦克风录音、语音识别、唤醒词或自动对话。
- 现有 `/chat` 与 `/ws/chat` 的请求和响应格式保持不变。

## 方案选择

采用 Mac 代理方案：

`ESP32 -> 芷春 /tts -> 智谱 GLM-TTS -> WAV -> ESP32 -> MAX98357 -> 喇叭`

即使设备仅供个人使用，Mac 代理仍能让智谱 API Key、模型名称、错误处理和后续音色切换留在服务端。更换 Key 或 TTS 时无需重新烧录固件。

ESP32 不直接调用智谱，也不使用返回临时下载地址的两阶段流程。

## 服务端接口

新增受现有 Bearer Token 保护的接口：

`POST /tts`

请求：

```json
{
  "text": "你好，我是芷春"
}
```

成功响应：

- HTTP `200`
- `Content-Type: audio/wav`
- 响应体为完整 WAV 文件
- 包含 `Content-Length`，便于 ESP32 规划读取
- 音频为智谱当前输出的 24 kHz、16-bit、单声道 PCM WAV

文本去除首尾空白后不能为空，最大长度与智谱接口一致，为 1024 个字符。

服务端先完整获取智谱响应，确认 HTTP 状态和 WAV 文件头后再返回给 ESP32。这样 ESP32 不会把智谱的 JSON 错误信息当作 PCM 播放。

## 局域网监听与安全

服务监听地址从硬编码改为环境变量 `HOST`，默认值仍为 `127.0.0.1`。ESP32 使用时在本地 `.env` 设置：

```env
HOST=0.0.0.0
```

端口继续使用 `8000`。ESP32 请求 Mac 的局域网 IPv4 地址，例如：

```text
http://192.168.1.20:8000/tts
```

ESP32 固件只保存芷春服务的 `API_TOKEN`。智谱 `ZHIPU_API_KEY` 始终保留在 Mac。服务不开放公网端口，路由器不配置端口转发。

## 智谱客户端

新增一个职责单一的 TTS 客户端模块：

- 从环境变量读取 `ZHIPU_API_KEY`。
- 调用 `https://open.bigmodel.cn/api/paas/v4/audio/speech`。
- 请求固定模型、音色和 WAV 格式。
- 设置连接和读取超时。
- 返回经过 WAV 头校验的字节。
- 将智谱余额不足、鉴权失败、超时和非音频响应映射为服务端可控异常。

日志只记录请求 ID、耗时、文本长度、上游状态和错误类型，不记录原文、API Key、API Token 或音频内容。

## ESP32 固件

新增 Arduino/PlatformIO 固件工程，用于验证从 Mac 请求并播放 TTS：

- 连接用户配置的 Wi-Fi。
- 向 `/tts` 发送带 Bearer Token 的 JSON 请求。
- 检查 HTTP 状态、`Content-Type` 和 WAV 头。
- 解析 PCM 数据偏移、采样率、位深和声道数。
- 以小块缓冲区从网络读取音频并写入 I²S，不把整段 WAV 放入内存。
- 只接受 24 kHz、16-bit、单声道 PCM；其他格式在串口输出明确错误并停止播放。

已确认音频硬件为 MAX98357（通常为 MAX98357A）和 4Ω 3W 喇叭。接线结构：

`ESP32 BCLK/LRC/DIN -> MAX98357 BCLK/LRC/DIN -> SPK+/SPK- -> 喇叭`

MAX98357 使用 5V 供电并与 ESP32 共地。`SPK-` 不是地线，喇叭只能接在 `SPK+` 与 `SPK-` 之间。

由于之前的硬件任务没有确认 ESP32 完整子型号，BCLK、LRC/WS 和 DIN 不写散在播放代码中，而是集中在固件配置文件里。烧录前根据开发板实际可用 GPIO 设置，避免 ESP32 与 ESP32-S3 的引脚差异造成误接。

INMP441 麦克风保留给后续语音输入阶段，本次不接入、不占用 I²S 引脚。

## 错误处理

- 请求未鉴权：返回现有统一 `401` JSON 错误。
- 文本为空或超过 1024 字符：返回现有统一 `422` JSON 错误。
- 未配置智谱 Key：返回安全的 `503` JSON 错误。
- 智谱余额不足、限流、超时或返回异常：返回安全的 `502` 或 `503` JSON 错误。
- 不向 ESP32 透传智谱响应正文中的敏感或不稳定细节。
- ESP32 遇到非 `200` 响应时只在串口显示状态与安全错误消息，不尝试播放。
- Wi-Fi 或播放中断后释放 HTTP 和 I²S 资源，允许下一次请求恢复。

## 测试与验收

服务端自动测试覆盖：

- `/tts` 需要 Bearer Token。
- 空文本和超长文本被拒绝。
- 成功时返回 `audio/wav`、正确长度和上游音频字节。
- 智谱 Key 缺失、超时、余额不足和非 WAV 响应被安全转换。
- 日志不包含文本、Key 或 Token。
- `HOST` 默认保持 `127.0.0.1`，并能通过环境变量设置为 `0.0.0.0`。
- 现有全部测试继续通过。

固件验收覆盖：

- PlatformIO 工程能针对最终确认的 ESP32 板型编译。
- ESP32 能连接同一局域网中的 Mac。
- 能请求一句短文本并连续播放三次。
- 串口能显示连接、请求、格式和播放完成状态。
- 音频无明显变速、截断或持续爆音。
- API Token 错误、Mac 服务未启动和智谱上游失败时不播放噪声，恢复后无需重新烧录。

## 暂不包含

- ESP32 麦克风采集与上传。
- ASR、唤醒词、回声消除和全双工语音。
- 把 `/chat` 与 `/tts` 自动串联。
- 公网访问、远程设备管理和 OTA。
- 自定义或复刻音色。
