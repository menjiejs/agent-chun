# 基础日志与错误处理设计

## 目标

让芷春 FastAPI 服务出错时可以定位原因，同时不在日志或接口响应中泄露聊天内容、访问令牌和内部异常细节。

## 范围

- 使用 Python 标准库 `logging`，不增加第三方日志依赖。
- 日志同时输出到终端和 `logs/agent.log`。
- 日志文件最大 5 MB，保留 5 个轮换文件。
- 每个 HTTP 请求记录请求编号、方法、路径、状态码和耗时。
- 已解析到的 `session_id` 可以记录；聊天原文、请求正文、API Token 和 API Key 禁止记录。
- 认证、参数校验、业务异常和未知异常返回统一 JSON 错误结构。
- 未知异常的堆栈只写入服务端日志，客户端收到通用提示。
- WebSocket 只记录连接、断开和错误类型，不记录消息内容。

## 接口行为

HTTP 错误响应使用以下结构：

```json
{
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "服务暂时不可用",
    "request_id": "请求编号"
  }
}
```

响应头包含 `X-Request-ID`。认证失败保留 `WWW-Authenticate: Bearer`。

WebSocket 出错时只发送安全的错误代码和提示，不返回 Python 异常文本。

- 修改 `app/server.py`：请求编号中间件、异常处理器和安全日志。

## 验收

- 正常请求与失败请求都有请求编号。
- 模拟 Agent 抛出包含敏感文本的异常时，响应不包含该异常文本。
- 测试日志内容不包含聊天原文或鉴权令牌。
- 原有鉴权、聊天和技能接口测试继续通过。
